## 🎯 قراره چیکار کنیم؟

بذار مثل یه داستان بگم:

🏠 **پنل تو** = خونه‌ی توئه که همه‌ی کاربرات (دوستات) توش زندگی می‌کنن.

☁️ **Cloudflare Worker** = یه انباری بزرگ توی آسمون که هر چی اضافه/کم می‌شه، یه کپی ازش اون‌جا هم ذخیره می‌شه.

🔑 **پسورد مخفی (Secret)** = یه رمز جادویی که فقط خونه‌ی تو و انباری آسمون بلدنش، تا کسی نتونه دزدی کنه.

---

## 🪜 مرحله ۱: ساختن انباری آسمون (Cloudflare Worker)

### 📍 کجا بری؟
👉 برو به این آدرس: **https://dash.cloudflare.com/**

### 👣 چیکار کنی؟

1. اگه اکانت نداری → **Sign Up** رو بزن (رایگانه، فقط ایمیل می‌خواد).
2. وارد شدی → از منوی چپ روی **Workers & Pages** کلیک کن.
3. دکمه‌ی آبی **Create application** → بعد **Create Worker** رو بزن.
4. یه اسم بهش بده، مثلاً: `sub-proxy` → بعد **Deploy** رو بزن.
5. تبریک! 🎉 حالا یه آدرس بهت داده مثل این:
   ```
   https://sub-proxy.esmeto.workers.dev
   ```
   این آدرسو یه جا نگه دار، بهش می‌گیم **آدرس انباری**.

---

## 🪜 مرحله ۲: توی انباری یه صندوق باز کنیم (KV Storage)

انباری خالیه، باید توش قفسه بذاریم که چیزا رو جا بدیم:

1. برگرد به داشبورد Cloudflare.
2. از منوی چپ: **Storage & Databases** → **KV**.
3. دکمه‌ی **Create a namespace** → اسمشو بذار: `BACKUPS` → **Add**.

---

## 🪜 مرحله ۳: کُد انباری رو بذاریم داخلش

1. برگرد به **Workers & Pages** → روی worker خودت (`sub-proxy`) کلیک کن.
2. بالا سمت راست دکمه‌ی **Edit code** یا **Quick edit**.
3. همه‌ی چیزی که اونجاست پاک کن، و **این کد رو کپی کن بذار:**

```js
export default {
  async fetch(req, env) {
    if (req.method !== "POST")
      return new Response("فقط POST!", { status: 405 });

    if (req.headers.get("X-Sync-Secret") !== env.CF_SYNC_SECRET)
      return new Response("رمز اشتباهه!", { status: 403 });

    const payload = await req.json();

    await env.BACKUPS.put("latest.json", JSON.stringify(payload));
    await env.BACKUPS.put(
      `events/${payload.timestamp_unix}-${payload.event_type}.json`,
      JSON.stringify(payload),
      { expirationTtl: 60 * 60 * 24 * 30 }
    );

    return Response.json({ ok: true, received: payload.event_type });
  },
};
```

4. دکمه‌ی **Save and Deploy** بالا سمت راست 🚀

---

## 🪜 مرحله ۴: انباری رو به قفسه (KV) وصل کن

1. توی همون صفحه‌ی Worker، برو تب **Settings**.
2. پیدا کن: **Variables and Secrets** یا **Bindings**.
3. بخش **KV Namespace Bindings** → **Add binding**:
   - **Variable name:** `BACKUPS` (دقیقاً همین!)
   - **KV namespace:** انتخاب کن → `BACKUPS`
4. **Save**.

---

## 🪜 مرحله ۵: رمز جادویی بساز 🗝️

توی همون صفحه‌ی **Settings → Variables and Secrets**:

1. دکمه‌ی **Add variable** → نوعش رو بذار **Secret** (نه Text!).
2. **Variable name:** `CF_SYNC_SECRET`
3. **Value:** یه رمز خیلی سخت بنویس، مثلاً:
   ```
   my-super-secret-password-123456
   ```
   💡 هرچی طولانی‌تر بهتر. این رمز رو **یه جا بنویس، لازمت می‌شه!**
4. **Save**.

---

## 🪜 مرحله ۶: حالا بریم سراغ پنل خودت (Railway)

### 📍 کجا بری؟
👉 برو به: **https://railway.app/** → وارد پروژه‌ی X4G خودت شو.

### 👣 چیکار کنی؟

1. روی سرویس (کارت پروژه‌ت) کلیک کن.
2. تب **Variables** (متغیرها) رو باز کن.
3. دکمه‌ی **+ New Variable** رو بزن و **این دوتا** رو اضافه کن:

**متغیر اول:**
- Name: `CF_WORKER_URL`
- Value: `https://sub-proxy.esmeto.workers.dev`
  *(آدرس worker خودت + همیشه آخرش هیچی اضافه نکن — کد ما خودش می‌فرسته)*

**متغیر دوم:**
- Name: `CF_SYNC_SECRET`
- Value: `my-super-secret-password-123456`
  ⚠️ **دقیقاً همون رمزی که تو مرحله ۵ ساختی** — یه حرف هم فرق نکنه!

4. **Save** رو بزن. Railway خودش سرویس رو ری‌استارت می‌کنه ♻️

---

## 🪜 مرحله ۷: تست کن ببین کار می‌کنه ✅

### راه اول: از داخل پنل
1. برو داشبورد پنل خودت.
2. یه کانفیگ جدید بساز، یا یکی رو حذف کن.
3. برو Cloudflare → **Workers & Pages → sub-proxy → Logs (Real-time Logs)**.
4. باید ببینی درخواست اومده! 🎉

### راه دوم: با URL دستی

⚠️ **اول تو پنل لاگین کن** (وگرنه خطای `unauthorized` می‌گیری)

بعد **تو همون مرورگر، تو همون تب**، آدرس زیر رو بزن:
```
https://آدرس-پنل-تو/api/cf-sync/status
```
اگه چیزی مثل این دیدی:
```json
{ "enabled": true, "sent_ok": 5, "sent_fail": 0, ... }
```
یعنی همه‌چی عالیه! ✨

### راه سوم: چک کن دیتا رسیده
1. برو Cloudflare → **Storage & Databases → KV → BACKUPS**.
2. تب **View** → باید یه فایل به اسم `latest.json` ببینی.
3. کلیک کن روش → دیتای پنلت اونجاست! 💾

# 🔧 رفع مشکلات

## ❌ خطای: `Name or service not known`

اگه توی خروجی `status` این رو دیدی:

```json
{
  "sent_ok": 0,
  "sent_fail": 2,
  "last_error": "[Errno -2] Name or service not known"
}
```

### 🔍 مشکل چیه؟

اینترنت می‌گه **«این آدرس اصلاً وجود نداره!»** 🕵️

مثل این می‌مونه که به آژانس بگی «منو ببر خونه‌ی esmeto» ولی همچین خونه‌ای اصلاً ساخته نشده! 🏚️

### 🎯 دلایل و راه‌حل:

#### احتمال ۱: آدرس worker غلط نوشته شده ✏️

`esmeto` یه مثاله! آدرس worker **تو** فرق داره.

**چطور آدرس درست رو پیدا کنی؟**

1. برو به **https://dash.cloudflare.com**
2. از منوی چپ: **Workers & Pages**
3. روی اسم worker خودت کلیک کن (اونی که مرحله ۱ ساختی)
4. بالای صفحه یه آدرس آبی می‌بینی، **دقیقاً** همون آدرس رو کپی کن. یه چیزی شبیه اینا:
   ```
   https://sub-proxy.YOUR-USERNAME.workers.dev
   ```

#### احتمال ۲: هنوز Deploy نکردی 🚀

اگه worker رو ساختی ولی **Save and Deploy** رو نزدی، آدرسش فعال نمیشه.

- برو Cloudflare → Workers & Pages → worker خودت
- اگه نوشته **"Not deployed yet"** → کد رو باز کن و **Deploy** رو بزن

#### احتمال ۳: تازه Deploy کردی و هنوز DNS آماده نشده ⏱️

بعضی وقت‌ها ۱-۲ دقیقه طول می‌کشه. یه کم صبر کن.

### ✅ چطور مطمئن بشی آدرس worker خودت کار می‌کنه؟

**قبل از هر کاری این تستو بکن:**

1. آدرس worker رو کپی کن.
2. بذارش تو **مرورگر** و Enter بزن.
3. باید یکی از این‌ها رو ببینی:

| چی می‌بینی؟ | یعنی چی |
|---|---|
| صفحه سفید با نوشته‌ی `فقط POST!` یا `Method Not Allowed` | ✅ عالیه! آدرس درسته |
| صفحه‌ی خطای Cloudflare با نوشته‌ی **"This site can't be reached"** یا **"DNS_PROBE_FINISHED_NXDOMAIN"** | ❌ آدرس غلطه یا Deploy نشده |
| صفحه‌ی زرد Cloudflare با نوشته‌ی **"Worker threw exception"** | ⚠️ Deploy شده ولی کد ایراد داره |

### 🔧 وقتی آدرس درستو پیدا کردی:

1. برگرد **Railway** → پروژه‌ی X4G → تب **Variables**.
2. متغیر `CF_WORKER_URL` رو پیدا کن و **Edit** کن.
3. آدرس **درست خودت** رو بذار.
   💡 نکته مهم: آخر آدرس هیچی اضافه نکن — نه `/api/push-backup` نه چیز دیگه. فقط آدرس ساده‌ی worker.
4. **Save** → Railway خودش سرویس رو ری‌استارت می‌کنه.
5. ۳۰ ثانیه صبر کن، بعد دوباره status رو چک کن.

## ❌ خطای: `unauthorized`

اگه توی مرورگر این رو دیدی:

```json
{ "detail": "unauthorized" }
```

### 🔍 چی شد؟

این خطا خیلی خوبه در واقع — یعنی امنیت پنلت درست کار می‌کنه! 🛡️

نوشته: `unauthorized` یعنی **«شما وارد نشدی!»** 🚪

این آدرس (`/api/cf-sync/status`) یه در قفله که فقط ادمین‌ها می‌تونن بازش کنن. مرورگر تو نمی‌دونه تو ادمینی، برای همین در رو باز نمی‌کنه.

مثل این می‌مونه که بری در خونه‌ی خودت ولی کلید همراهت نباشه! 🔑

### ✅ راه حل: اول برو تو پنل لاگین کن

**۱.** برو به داشبورد پنل خودت (همون آدرس معمولی که همیشه می‌ری):
```
https://آدرس-پنل-تو/dashboard
```

**۲.** رمز ادمین رو بزن و وارد شو (همون `X4GKING` یا هرچی خودت گذاشتی).

**۳.** حالا که وارد شدی، **تو همون مرورگر، تو همون تب**، آدرس زیر رو بزن:
```
https://آدرس-پنل-تو/api/cf-sync/status
```

**۴.** حالا باید چیزی مثل این ببینی:
```json
{
  "enabled": true,
  "worker_url": "https://sub-proxy.esmeto.workers.dev",
  "sent_ok": 5,
  "sent_fail": 0,
  ...
}
```

## ❌ خطای: `HTTP 403` (رمز اشتباهه)

اگه توی خروجی `status` این رو دیدی:

```json
{
  "sent_ok": 0,
  "sent_fail": 2,
  "last_error": "HTTP 403: رمز اشتباهه!"
}
```

### ✅ خبر خوب چیه؟

- ✅ آدرس worker درسته (پیدا کرد!)
- ✅ Worker داره جواب می‌ده
- ✅ کدی که تو Cloudflare گذاشتی داره کار می‌کنه (چون خطای فارسی «رمز اشتباهه!» رو خودش برگردوند 😄)

### ❌ فقط یه مشکل کوچیک:

پنل می‌گه: **«رمز من `abc` هست»** 🗝️
Worker می‌گه: **«نه! رمز من `xyz` هست، تو رو نمی‌شناسم!»** 🚫

یعنی **دوتا رمز با هم فرق دارن**. باید یکسان بشن.

### 🎯 راه حل: رمزها رو یکسان کن

#### 👣 مرحله ۱: برو رمز Cloudflare رو ببین (یا عوضش کن)

**نکته مهم:** Cloudflare بعد از ساختن Secret، دیگه بهت **نشونش نمی‌ده** (به خاطر امنیت). پس بهترین کار اینه که **یه رمز جدید بسازی و توی جفتشون بذاری**.

1. برو به: **https://dash.cloudflare.com**
2. از منوی چپ: **Workers & Pages**
3. روی worker خودت کلیک کن
4. برو تب **Settings**
5. پایین برو تا **Variables and Secrets** رو ببینی
6. اگه یه ردیف به اسم `CF_SYNC_SECRET` می‌بینی:
   - سه نقطه (⋯) کنارش → **Delete** بزن
   - بعد **+ Add** رو بزن
7. یه Secret جدید بساز:
   - Type: **Secret** (حتماً Secret، نه Text!)
   - Variable name: `CF_SYNC_SECRET`
   - Value: یه رمز ساده و قابل کپی، مثلاً:
     ```
     MyPanelSecret2026XYZ
     ```
   ⚠️ **این رمز رو یه جا کپی کن، الان لازمت می‌شه!**
8. **Deploy** رو بزن.

#### 👣 مرحله ۲: همون رمز رو تو Railway هم بذار

1. برو **https://railway.app** → پروژه‌ی X4G
2. روی سرویس کلیک کن → تب **Variables**
3. متغیر `CF_SYNC_SECRET` رو پیدا کن → کنارش دکمه‌ی ✏️ (Edit)
4. مقدارش رو پاک کن و **دقیقاً همون رمز** رو بذار:
   ```
   MyPanelSecret2026XYZ
   ```
   ⚠️ **هیچ فاصله‌ای اول یا آخرش نباشه!** حتی یه فاصله اضافی هم باعث خطا می‌شه.
5. **Update** یا **Save** رو بزن.
6. Railway خودش سرویس رو Restart می‌کنه (۳۰ ثانیه صبر کن).

#### 👣 مرحله ۳: دوباره تست کن

1. برو پنل، لاگین کن.
2. یه کانفیگ جدید بساز (یا یکی رو ویرایش کن).
3. آدرس status رو باز کن.
4. حالا باید ببینی:
```json
{
  "enabled": true,
  "sent_ok": 1,          ← این باید بالا رفته باشه ✅
  "last_ok_at": "2026-...",  ← این پر شده ✅
  "last_event": "USER_CREATED"   ← این پر شده ✅
}
```

### 💡 اگه هنوز `HTTP 403` می‌ده:

یعنی رمز هنوز فرق داره. این چیزا رو چک کن:

- ❌ فاصله‌ی اضافی اول یا آخر رمز؟
- ❌ حروف بزرگ/کوچیک فرق داره؟ (`MyPassword` با `mypassword` فرق داره!)
- ❌ یه علامت اضافه مثل `"` یا فاصله؟
- ❌ توی Cloudflare **Deploy** رو نزدی؟
- ❌ توی Railway بعد از Save، سرویس ری‌استارت نشده؟

# 🎊 وقتی موفق شدی چی می‌بینی

خروجی status باید این‌شکلی بشه:

```json
{
  "enabled": true,
  "worker_url": "https://snapp.jjgadradan.workers.dev",
  "interval_sec": 900,
  "sent_ok": 1,
  "sent_fail": 0,
  "last_ok_at": "2026-08-20T19:40:16.651947",
  "last_fail_at": null,
  "last_error": null,
  "last_event": "CRON_AUTO_SYNC"
}
```

### 🎁 ترجمه‌ش این می‌شه:

| چی نوشته | یعنی چی |
|---|---|
| `enabled: true` | ✅ ماژول روشنه و کار می‌کنه |
| `sent_ok: 1` | ✅ **یه بکاپ با موفقیت رسید تو انباری آسمون!** |
| `sent_fail: 0` | ✅ هیچ خطایی نداشته 🎯 |
| `last_ok_at: "..."` | ✅ آخرین باری که بکاپ رفت |
| `last_event: "CRON_AUTO_SYNC"` | ✅ خودکار هر ۱۵ دقیقه یه بار داره کار می‌کنه ⏰ |

### 🎯 حالا از این به بعد چی می‌شه؟

- 🆕 **هر کاربر جدید بسازی** → فوراً یه کپی می‌ره Cloudflare
- ✏️ **هر ویرایشی بکنی** → فوراً می‌ره Cloudflare
- 🗑️ **هر حذفی بکنی** → فوراً می‌ره Cloudflare
- ⏰ **هر ۱۵ دقیقه هم** خودکار یه بکاپ کامل می‌ره

**دیگه هیچوقت دیتات از بین نمی‌ره!** 💾✨

# 🚨 اگه پنل Railway از دست رفت — پنل جدید چطور بیاری بالا؟

## 🎯 اول یه چیز مهم بگم:

الان دیتات **دو جا** ذخیره شده:
- 🏠 یکی تو Railway (که ممکنه پاک بشه)
- ☁️ یکی تو Cloudflare (که **هیچوقت پاک نمی‌شه**) ✨

پس اگه Railway از دستت رفت، هیچ‌چیزی از دست نداده‌ای! 💪

---

## 🪜 مرحله ۱: اول دیتای بکاپ رو از Cloudflare دانلود کن

1. برو به: **https://dash.cloudflare.com**
2. از منوی چپ: **Storage & Databases** → **KV**
3. روی `BACKUPS` کلیک کن
4. تب **View** یا **KV Pairs** رو بزن
5. یه ردیف به اسم `latest.json` می‌بینی → روش کلیک کن
6. یه پنجره باز می‌شه با کلی نوشته‌ی عجیب `{...}` — این **دیتای پنلته!** 💾
7. همه‌ی محتوا رو **Select All** کن (Ctrl+A) و **Copy** کن (Ctrl+C)
8. برو تو کامپیوترت **Notepad** (یا هر ویرایشگر متن) رو باز کن، بذار توش (Ctrl+V)
9. ذخیره کن با اسم `backup.json` روی دسکتاپ 💾

✅ **دیتای پنلت الان تو کامپیوترته!**

---

## 🪜 مرحله ۲: پنل جدید تو Railway بساز

1. برو **https://railway.app**
2. دکمه‌ی **+ New Project** رو بزن
3. **Deploy from GitHub repo** رو انتخاب کن
4. همون ریپازیتوری X4G خودت رو انتخاب کن
5. صبر کن Railway پروژه رو Deploy کنه (۱-۲ دقیقه) ⏱️

---

## 🪜 مرحله ۳: Volume دائمی بساز (خیلی مهم!) 💾

اگه این کار رو نکنی، هر بار سرور ری‌استارت شه دیتات پاک می‌شه!

1. رو سرویس کلیک کن
2. تب **Settings** رو باز کن
3. پایین بیا تا **Volumes** رو ببینی
4. دکمه‌ی **+ New Volume** رو بزن
5. توی **Mount Path** بنویس: `/data`
6. **Add** رو بزن ✅

---

## 🪜 مرحله ۴: متغیرهای محیطی رو اضافه کن

1. برو تب **Variables**
2. این متغیرها رو یکی یکی اضافه کن:

| نام متغیر | مقدار |
|---|---|
| `ADMIN_PASSWORD` | یه رمز برای پنل (مثلاً `MyPanel2026`) |
| `CF_WORKER_URL` | `https://snapp.jjgadradan.workers.dev` |
| `CF_SYNC_SECRET` | **همون رمز جادویی قبلی** (مثل `MyPanelSecret2026XYZ`) |

⚠️ **نکته مهم:** `CF_SYNC_SECRET` باید **دقیقاً همون رمزی باشه که تو Cloudflare گذاشتی** — تا پنل جدید هم بتونه به همون انباری آسمون وصل شه!

3. Railway خودش سرویس رو Restart می‌کنه.

---

## 🪜 مرحله ۵: دامنه‌ی عمومی بگیر 🌐

1. تب **Settings** → پایین بیا تا **Networking** رو ببینی
2. دکمه‌ی **Generate Domain** رو بزن
3. یه آدرس بهت می‌ده مثل:
   ```
   https://x4g-production-abc123.up.railway.app
   ```
4. این آدرسو یه جا نگه دار! 📝

---

## 🪜 مرحله ۶: 🔥 مهم‌ترین قسمت — برگردوندن دیتا! 🔥

الان پنلت بالا اومده ولی **خالیه**. باید دیتای بکاپ رو بذاری داخلش.

### راه ۱: از طریق Railway CLI (پیشرفته)

اگه بلدی، فایل `backup.json` رو بذار تو مسیر `/data/x4g_state.json` سرور.

### راه ۲: راه ساده‌تر — از خود Railway 💡

1. برو Railway → سرویس خودت → تب **Settings** → پایین **Volumes** → یه دکمه‌ی **Browse** یا **Files** می‌بینی
2. برو تو مسیر `/data`
3. اگه فایل `x4g_state.json` هست → پاکش کن
4. فایل جدید بساز به اسم `x4g_state.json`
5. محتوای `backup.json` که تو دسکتاپت داری رو کپی کن → بذار توی این فایل
6. ذخیره کن 💾
7. سرویس رو Restart کن (از منوی سه نقطه‌ی سرویس → Restart)

---

## 🪜 مرحله ۷: تست کن ✅

1. برو آدرس پنل جدیدت:
   ```
   https://x4g-production-abc123.up.railway.app/dashboard
   ```
2. با رمز `ADMIN_PASSWORD` که گذاشتی وارد شو
3. **باید همه‌ی کانفیگ‌های قبلیت رو ببینی!** 🎉
4. برو بررسی کن status هم درسته:
   ```
   https://x4g-production-abc123.up.railway.app/api/cf-sync/status
   ```

اگه `sent_ok` بالا رفت و `enabled: true` بود → 🎊 موفق شدی!

## ⚠️ نکات خیلی مهم:

### 🔑 نکته ۱: رمز `CF_SYNC_SECRET` رو یه جای امن نگه دار!
اگه اینو گم کنی، دیگه نمی‌تونی دیتا رو از Cloudflare بگیری. یه بار همین الان تو یه فایل امن (مثل Google Keep یا Notes گوشیت) ذخیره‌ش کن! 📱

### 🌐 نکته ۲: آدرس Worker همینه که هست
لازم نیست Worker جدید بسازی. همون `snapp.jjgadradan.workers.dev` که داری، برای پنل جدیدت هم کار می‌کنه ✨

### ⏱️ نکته ۳: چقدر صبر کنی؟
کل این پروسه **حداکثر ۱۰-۱۵ دقیقه** طول می‌کشه. اصلاً سخت نیست! 💪

### 🔄 نکته ۴: بلافاصله بعد از راه‌اندازی
اولین چیزی که پنل جدیدت می‌کنه اینه که خودش هم شروع می‌کنه به بکاپ گرفتن. یعنی از همون لحظه‌ی اول دیتات دوباره داره ذخیره می‌شه! 🎯
